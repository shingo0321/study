# 4. Workflow Integration and Solution Design(ワークフロー統合とソリューション設計)出題比率 目安: 16%

## この分野が扱うこと

Claudeを単発のQ&Aツールとしてではなく、業務プロセス・ワークフローの一部として組み込み、繰り返し使える「ソリューション」として設計する視点。どの業務にClaudeが向いているかの見極め、複数ステップのプロセス設計、人間とAIの役割分担、既存ツール(Slack、社内システム、API連携)との統合パターンを扱う。

## Claudeを組み込むのに向いているタスクの見極め

- **繰り返し発生する定型的な言語処理タスク** — 要約、分類、下書き作成、翻訳、抽出、フォーマット変換など。人手でやると時間がかかるが、判断基準を言語化しやすいタスクほど自動化・半自動化に向く。
- **判断の一次スクリーニングを任せ、最終判断は人間が行うタスク** — 例:問い合わせメールの一次分類・優先度付けはClaudeに任せ、実際の対応方針決定は担当者が行う。
- **向かないタスクの見極めも重要** — 高いリスク(法的拘束力、安全性、機密性の高い最終判断)を伴い、誤りの許容度が低いタスクをClaude単独の判断に委ねるのは不適切。あくまで人間の意思決定を支援する位置づけにする。

## ワークフロー設計の基本パターン

- **単発利用(One-shot)** — 都度チャットで質問・依頼する最もシンプルな形。頻度が低い、毎回文脈が異なるタスクに向く。
- **継続利用(Projects型)** — 同じ業務文脈・ナレッジを繰り返し参照するタスクは、Claude.aiのProjectsのようにナレッジと指示を固定化した環境で行うと、毎回のプロンプト作成コストが下がり出力の一貫性も上がる。
- **API/システム統合型** — 既存の業務システム(CRM、社内ポータル、チケット管理ツールなど)からAPI経由でClaudeを呼び出し、処理結果を自動的に次の工程へ流す。人手を介さない自動化パイプラインの構築に向くが、その分、出力検証の仕組みを設計に組み込む必要がある。
- **チャットツール統合型** — Slackなど既に業務で使われているコミュニケーションツールの中にClaudeを組み込み、利用のハードルを下げる。

## 複数ステップのタスク分解設計

- 複雑な業務プロセスは、Claudeに一括で任せるのではなく、**工程ごとに分割**し、各工程の出力を検証してから次に渡す設計にすると、誤りの発見・修正がしやすく、全体の信頼性が上がる(例:①資料から情報抽出 → ②抽出結果の人間チェック → ③抽出結果をもとに文書生成)。
- 各ステップで「入力」「Claudeへの指示」「期待する出力形式」「検証方法」を明確に定義しておくことが、再現性のあるワークフロー設計の基本。
- 前工程の出力形式(JSON、表など)を後工程が扱いやすい形に揃えておくと、システム連携がスムーズになる。

## 人間とAIの役割分担(Human-in-the-loop設計)

- Claudeは「下書き・一次案・一次分類」を高速に生成する役割、人間は「最終判断・承認・例外対応」を担う役割、という分担が典型的な安全設計。
- リスクが高い/影響が大きい意思決定ほど、人間のレビューを必須のチェックポイントとしてワークフローに組み込む。
- 例外処理(Claudeが自信を持てない、判断がつかない、通常と異なるパターンのケース)を検知して人間にエスカレーションする仕組みをあらかじめ設計しておくことが、実務での信頼性確保につながる(詳細は分野7「トラブルシューティングとエスカレーション」も参照)。

## 既存ツール・システムとの統合の考え方

- Claude.aiのProjectsのナレッジ機能に業務資料をまとめておくことで、繰り返し同じ前提を説明するコストを下げられる。
- APIを使うと、社内システムのデータをClaudeに渡し、処理結果をシステムに書き戻す自動化フローを構築できる(例:問い合わせ内容の要約をチケット管理システムに自動反映)。
- 統合を設計する際は、機密情報の取り扱い(どのデータをClaudeに渡してよいか)、処理結果の検証ステップ、失敗時のフォールバック(人間による代替対応)を必ず考慮する。

## 押さえておくべきポイント

- 定型的・反復的で判断基準を言語化しやすいタスクほどClaude組み込みに向くという見極め基準を説明できること。
- 単発利用/継続利用(Projects)/API統合/チャットツール統合という統合パターンの違いを理解していること。
- 複雑なタスクは工程分解し、各工程に検証ポイントを設けるワークフロー設計ができること。
- 人間とAIの役割分担(Claude=一次案・下書き、人間=最終判断)という設計原則を理解していること。
- 統合設計時にデータの機密性・検証・失敗時のフォールバックを考慮する視点を持つこと。
