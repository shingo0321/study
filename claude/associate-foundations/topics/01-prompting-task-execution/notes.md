# 1. Prompting and Task Execution(プロンプト設計とタスク実行)出題比率 目安: 14%

## この分野が扱うこと

Claudeに対して、意図した通りの出力を得るためのプロンプトの組み立て方。ビジネスユーザーが日常業務(要約・分類・文書生成・分析など)でClaudeを使う際に、どう指示すれば精度・再現性が上がるかという実務スキルが問われる。開発者向けAPIパラメータの細部ではなく、「良いプロンプトとは何か」「タスクをどう分解して指示するか」が中心。

## プロンプトの基本構成要素

- **役割(ロール)指定** — 「あなたは経験豊富な財務アナリストです」のように、Claudeに担わせる役割・専門性・視点を先に与える。出力のトーンや専門用語の選択、注目するポイントが変わる。
- **文脈(コンテキスト)** — なぜこのタスクをやるのか、誰向けの出力か、前提知識をどこまで共有できているかを明示する。文脈が薄いと一般論的な出力になりやすい。
- **タスクの明確な指示** — 「何を」「どう」「どんな形式で」を具体的に書く。動詞を曖昧にしない(例:「まとめて」より「300字以内で3つの箇条書きに要約して」)。
- **出力フォーマットの指定** — 表形式、JSON、見出し付き箇条書きなど、後工程で使いやすい形を指定する。フォーマット例を1つ示すと再現性が上がる。
- **制約条件** — 文字数、対象読者、避けるべき表現、参照してよい情報源の範囲などを明示する。

## プロンプト技法

- **ゼロショット(Zero-shot)** — 例を与えずタスクを直接指示する。単純で汎用性の高いタスクに向く。
- **少数例示(Few-shot prompting)** — 望ましい入出力のペアを2〜3個示してから本番のタスクを依頼する。出力形式や粒度を揃えたいときに特に有効。入出力例の一貫性が重要(例がバラバラだとClaudeも一貫しない)。
- **思考の連鎖(Chain-of-thought / CoT)** — 「ステップごとに考えてから結論を出して」と指示し、推論過程を明示的に出力させる。複雑な計算・多段階の判断・込み入った分析タスクの精度を上げる。最終回答だけでなく途中の推論を検証できる利点もある。
- **XMLタグによる構造化** — `<document>`, `<instructions>`, `<example>` のようなタグでプロンプト内の要素を区切ると、Claudeが「どこが参考資料でどこが指示か」を誤解しにくくなる。長文プロンプトや複数の資料を渡すときに有効。Claudeは特にXMLタグでの構造化と相性が良いとされる。
- **システムプロンプト** — 対話全体を通じて一貫させたい役割・制約・出力ルールを、ユーザーの個別質問とは別に設定する仕組み。Claude.aiのProjectsの「カスタム指示」やAPIの `system` パラメータに相当する概念。毎回同じ前提を書き直さずに済む。
- **段階的な指示分解(タスク分解)** — 一度に大きく複雑な指示を出すより、「まず情報を抽出→次に分類→最後に要約」のように工程を分けて依頼する方が精度が安定することが多い。特に複数ステップのワークフローでは、各ステップの出力を人間またはClaude自身が確認してから次に進めると誤りの伝播を防げる。
- **明確化・反復(イテレーション)** — 一発で完璧な出力を狙うより、まず出力させてから「もっと簡潔に」「この部分を修正して」と対話的に洗練させていくアプローチも実務的で有効。

## 拡張思考(Extended Thinking)

Claudeが最終回答を出す前に、内部的に長く「考える」時間を与えるモード。複雑な数学・多段階推論・込み入った意思決定支援などで回答の質が向上しやすい。ただし全てのタスクに必要なわけではなく、単純な要約や定型的な生成タスクではオーバーヘッド(応答時間・コスト)が増えるだけで効果が薄い。タスクの複雑さに応じて使い分ける判断が重要。

## 良いタスク指示の設計原則

- **具体性** — 「良い感じに」ではなく、評価基準そのものを言語化する(誰向けか、長さ、トーン、含めるべき/避けるべき要素)。
- **明確な成功基準** — 何が出力できれば成功かを事前に定義しておくと、後工程の評価がしやすい。
- **曖昧な指示は曖昧な出力を生む** — Claudeは指示にない前提を勝手に補うことがあるため、重要な制約は明示する。
- **長いコンテキストの活用** — 参考資料やデータを貼り付けて「この資料に基づいて」と指示すると、Claudeの一般知識ではなく提供資料に基づいた回答を引き出しやすい(ハルシネーション対策にもなる)。

## 押さえておくべきポイント

- ロール・文脈・タスク・フォーマット・制約の5要素を意識してプロンプトを組み立てられること。
- Few-shotは「出力の型」を揃えたいときに有効、CoTは「複雑な推論」の精度を上げたいときに有効、と使い分けられること。
- XMLタグは長文・複数資料を扱うプロンプトの構造化に有効。
- システムプロンプトと個別のユーザー指示の役割の違いを理解していること。
- 拡張思考は「複雑なタスクにのみ」有効に使う判断ができること(万能ではない)。
- 大きなタスクは分解し、必要なら人間が中間チェックを挟む設計ができること。
