# 3. Product and Model Selection(製品とモデルの選択)出題比率 目安: 12%

## この分野が扱うこと

Anthropicが提供する製品群(Claude.ai、Claude Developer Platform/API、Claude Code、Claude in Slack「Claude Tag」など)と、モデルの階層(Haiku / Sonnet / Opus)の特徴を理解し、business/productivityユースケースに対して「どの製品」「どのモデル」を選ぶべきかを判断できるかを問う分野。開発の詳細ではなく、業務要件に対する適切な選択眼が問われる。

## Claudeの製品ラインナップ(概観)

- **Claude.ai** — 一般ユーザー・ビジネスユーザー向けのチャットインターフェース。個人利用向けプラン(Free/Pro)と、チーム・組織向けプラン(Team/Enterprise)がある。ブラウザ・デスクトップ・モバイルアプリから利用可能。
- **Projects(プロジェクト)** — Claude.ai上で、特定の業務・トピックごとに会話を整理し、参照資料(ナレッジ)やカスタム指示(システムプロンプト相当)をまとめて設定できる機能。同じ文脈を毎回貼り付けずに継続的な作業ができる。
- **Artifacts** — Claudeが生成したコード・文書・図表・簡易Webアプリなどを、チャットの流れとは別のパネルで表示・編集・反復できる機能。資料や成果物を独立した「モノ」として扱いたいときに使う。
- **Claude Developer Platform(API)** — 開発者・システム統合向けにClaudeをAPI経由で呼び出す基盤。自社アプリやワークフローにClaudeを組み込む用途。
- **Claude Code** — ソフトウェア開発者向けのCLI/エージェント型コーディング支援ツール。本試験(Associate)の主対象ではないが、製品ラインナップの一部として名前と用途を把握しておく。
- **Claude in Slack(Claude Tag)** — Slackワークスペース内で `@Claude` のようにメンションして直接対話できる統合。日常のコミュニケーションツール内でClaudeを使いたい場合に適する。
- **クラウド経由の提供** — Amazon Bedrock、Google Cloud Vertex AI経由でもClaudeモデルを利用可能(既存のクラウド基盤・ガバナンス体制に統合したい企業向け)。

## モデルの階層と選び方

Anthropicのモデルは概ね「速度・コスト」と「能力・推論の深さ」のトレードオフで階層化されている。

- **Haiku** — 最も高速・低コスト。定型的な分類、簡単な要約、大量データの一括処理、リアルタイム応答が求められるチャットボットなど、スピードとコスト効率が優先されるタスクに向く。
- **Sonnet** — 速度とコストと高度な能力のバランスが取れたモデル。多くの日常業務(文書作成、分析、コーディング支援、複雑な要約)で「まず試す」標準的な選択肢になることが多い。
- **Opus** — 最も高い推論能力を持つモデル。複雑な多段階の分析、高度な戦略立案、非常に込み入った専門的タスクなど、精度が最優先でコスト・速度が二の次になる場面に向く。

### 選定の考え方(試験で問われやすい視点)

- タスクの複雑さに対して過剰なモデルを使うとコスト・レイテンシの無駄になる。逆に単純な処理に見えて実は文脈理解や高度な判断が必要な場合、下位モデルでは品質が不足することがある。
- **「まず軽量モデルで試し、品質が不足する場合に上位モデルへ」**という段階的な検証アプローチが実務的。
- 大量・高頻度の処理(例:毎日大量の問い合わせを一次分類する)ではコスト効率の高いモデルを選び、少数だが重要な意思決定支援ではより高性能なモデルを選ぶ、という業務特性に応じた判断が問われる。
- 同じタスクでも「精度がビジネス上どれだけ重要か」「間違えたときの損失の大きさ」によって適切なモデルは変わる。

## 製品選択の考え方

- 個人が単発でClaudeに質問・相談したい → Claude.ai(チャット)。
- 継続的に同じ業務文脈で使いたい、資料をまとめておきたい → Claude.aiのProjects。
- 生成物(レポート、コード、図表)を独立して編集・保存・共有したい → Artifacts。
- 既存の社内システムやワークフローに組み込みたい → API(Claude Developer Platform)。
- 既にSlackが業務コミュニケーションの中心 → Claude in Slack。
- 既存のAWS/GCP基盤・調達契約・ガバナンス体制を使いたい → Bedrock/Vertex AI経由の利用。

## 押さえておくべきポイント

- Haiku/Sonnet/Opusのポジショニング(速度・コスト vs 能力)を説明でき、業務シナリオに対して適切なモデルを選べること。
- Claude.ai、Projects、Artifacts、API、Claude Codeの用途の違いを区別できること。
- 「まず軽量に試し、必要なら上位モデルへ」という段階的選定の考え方を理解していること。
- コストとリスク(間違えた場合の影響度)のバランスでモデル・製品を選ぶ視点を持つこと。
