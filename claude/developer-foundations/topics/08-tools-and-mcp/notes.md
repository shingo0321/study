# Tools and MCPs（10.6%）

Claudeにツールを持たせる仕組み全般を扱うドメイン。ツールユースの基礎に加え、Model Context Protocol（MCP）の概念（サーバー、リソース、ツール、トランスポート）、カスタムツールの構築、MCPサーバーの設定を中心に扱う。

## ツールの基本設計

- ツールは「名前」「説明（description）」「入力スキーマ（JSON Schemaベース）」の3要素で定義する。Claudeはこれを見て、いつ・どんな引数でそのツールを呼ぶべきかを判断する。
- **description の質が呼び出し精度を左右する**：何をするツールか、いつ使うべきか（逆にいつ使うべきでないか）、引数の意味を明確に書く。曖昧・重複した説明は誤呼び出しやツール選択ミスの原因になる。
- ツールは「副作用のない読み取り専用ツール」と「状態を変更する書き込み/実行系ツール」を分けて設計し、後者にはより慎重な権限制御を敷くのが望ましい（Security and Safetyドメインとも関連）。
- ツールの数が多すぎると選択精度が下がることがある。関連性の低いツールをまとめて常時提供するのではなく、タスクに応じて必要なツールだけを絞り込むことも設計上の工夫になる。

## Model Context Protocol（MCP）とは

- **MCP（Model Context Protocol）**は、LLMアプリケーションと外部のデータソース・ツールを接続するための、Anthropicが公開したオープンな標準プロトコル。
- 目的は「N個のアプリケーションをM個のデータソース/ツールに接続する」際の組み合わせ爆発（N×Mの個別統合）を、共通プロトコルによって解消すること（USBのような共通インターフェースに例えられる）。
- MCPを使うことで、一度作ったMCPサーバーを、Claude Desktop・Claude Code・自作のAgent SDKアプリケーションなど複数のクライアントから再利用できる。

## MCPの構成要素

- **MCPサーバー（MCP Server）**：特定のデータソースやシステム（ファイルシステム、DB、外部SaaS APIなど）へのアクセスを提供するプロセス。ツール・リソース・プロンプトなどを公開する。
- **MCPクライアント（MCP Client）**：MCPサーバーに接続し、公開された機能をLLMアプリケーション（ホスト）が使えるようにする側。Claude Desktop、Claude Code、Agent SDKベースのアプリなどがホストとしてクライアントを内包する。
- **ツール（Tools）**：サーバーが公開する「実行可能なアクション」。LLMが呼び出すことを想定した機能（例：ファイルを書き込む、APIを呼ぶ、検索する）。
- **リソース（Resources）**：サーバーが公開する「読み取り可能なデータ」。ツールと異なり、アプリケーション側（またはユーザー）がコンテキストに含めるデータを選択する用途を想定したもの。
- **プロンプト（Prompts）**：サーバー側で定義済みの、再利用可能なプロンプトテンプレート。ユーザーが特定のワークフローを素早く起動するために使う。

## トランスポート

- MCPのクライアント・サーバー間通信には複数のトランスポート方式がある。
  - **stdio（標準入出力）**：ローカルで動作するサーバーとの通信に使われる、シンプルな方式。ローカルツール・ローカルファイルアクセスなどに向く。
  - **HTTP（Streamable HTTP等のネットワーク経由の方式）**：リモートサーバーとの通信に使われる方式。リモートでホストされたMCPサーバーに接続する場合に利用する。
- どちらの方式でも、プロトコル上でやり取りされるメッセージの意味（ツール呼び出し、リソース取得など）自体は共通しており、トランスポートは「どう届けるか」の違いという位置づけ。

## カスタムツール／MCPサーバーの構築

- 自社の内部システム（社内DB、独自SaaS、社内API等）にClaudeからアクセスさせたい場合、その窓口となるMCPサーバーを自作するのが典型パターン。
- サーバー実装では、公開するツール・リソースの粒度設計（何を1つのツールとして切り出すか）、認証（APIキー・OAuthなど、サーバー自体がバックエンドシステムへの認証をどう扱うか）、エラーハンドリングが主な設計ポイントになる。
- ツールの入力スキーマは厳密に定義し、想定外の入力に対するバリデーションをサーバー側でも行う（LLM側の出力を無条件に信頼しない、というSecurity and Safetyの原則と共通）。

## MCPサーバーの設定・利用（クライアント側）

- Claude Code・Claude DesktopなどのホストアプリケーションでMCPサーバーを利用する場合、設定ファイルにサーバーの起動コマンド（stdioの場合）や接続先URL（HTTPの場合）、認証情報を記述して登録する。
- 設定はプロジェクト単位・ユーザー単位など複数のスコープで持てることが多く、チームで共有する設定と個人環境固有の設定を分離できる。
- 接続したMCPサーバーが公開するツールは、ホスト側の通常のツールと同様にパーミッション制御（許可/拒否/確認）の対象になる——外部提供のMCPサーバーを無条件に信頼せず、権限を絞って導入するのが望ましい。

## 押さえておくべきポイント

- ツール定義の3要素（名前・description・入力スキーマ）と、description の質が呼び出し精度を左右することを説明できる。
- MCPが「N×M統合問題」を解消するための共通プロトコルであるという目的を説明できる。
- MCPの主要な構成要素（サーバー/クライアント、ツール/リソース/プロンプト）の役割の違いを区別できる。
- stdio（ローカル）とHTTP（リモート）という2種類のトランスポートの使い分けを理解している。
- カスタムMCPサーバー構築時の設計ポイント（粒度設計、認証、入力バリデーション）を挙げられる。
- 外部提供のMCPサーバーも通常のツール同様パーミッション制御・最小権限の対象であることを理解している。
