# Claude Code（3.1%）

Anthropic公式のターミナル/CLIベースのコーディングエージェント「Claude Code」の使い方・仕組みを扱うドメイン。出題比重は小さいが、CLI操作・フック・スラッシュコマンド・MCP連携・設定/パーミッション・サブエージェントなど、基本機能を一通り押さえておく必要がある。

## Claude Codeとは

- ターミナル上で動作するエージェント型のコーディングアシスタント。リポジトリのファイルを読み書きし、コマンドを実行し、テストを回すなど、開発ワークフローを自律的に進められる。
- Claude Agent SDKの上に構築されており、「実際のプロダクトとして磨き上げられたエージェントの実例」という位置づけでもある（Applications and Integrationドメインとの関連）。
- IDE統合（VS Code拡張等）やGitHub Actions連携など、ターミナル単体に留まらない使い方も提供されている。

## CLIの基本操作

- 対話セッションを起動し、自然言語でタスクを依頼する基本的な使い方に加え、非対話（ヘッドレス）モードでスクリプトやCI/CDパイプラインから呼び出す使い方もある。
- セッション内では、ファイル編集・シェルコマンド実行・Git操作などをClaudeが提案/実行し、必要に応じてユーザーの承認を求める。
- 会話履歴のクリアや再開、直前の操作の取り消しなど、セッション管理のための操作が用意されている。

## スラッシュコマンド

- `/` で始まるコマンドにより、特定の定型タスク（例：初期化、レビュー、コミット支援など）をワンアクションで呼び出せる。
- ユーザー・プロジェクト側で**カスタムスラッシュコマンド**を定義することも可能で、よく使うプロンプトのテンプレート化・チーム内での標準化に使える。
- ビルトインコマンドとカスタムコマンドが共存し、プロジェクトごとに使えるコマンドセットをカスタマイズできる。

## フック（Hooks）

- Claude Codeの動作の特定タイミング（ツール実行前後、セッション開始/終了など）で、任意のシェルコマンドを自動実行できる仕組み。
- 用途例：コード編集後に自動でリンタ/フォーマッタを走らせる、特定の危険なコマンドをブロックする、操作ログを記録する。
- 「モデルに指示するだけでは確実性が保てない、決定論的に必ず実行してほしい処理」をフックとして仕込むのが基本的な考え方（例えば「毎回○○して」という繰り返し依頼は、記憶ではなくフックで解決すべき対象）。

## MCP連携

- Claude CodeはMCPクライアントとしても機能し、外部MCPサーバーを設定に追加することで、社内システムや各種SaaSへのアクセスをエージェントに与えられる（詳細はTools and MCPsドメイン参照）。
- プロジェクト単位・ユーザー単位でMCPサーバーの設定を分離でき、チーム共有の設定と個人環境固有の設定を使い分けられる。

## 設定とパーミッション

- 設定ファイル（settings.json等）により、許可するツール・コマンド、実行前に確認を求めるかどうか、自動承認の範囲などを細かく制御できる。
- パーミッションはプロジェクト単位・ユーザー単位など複数のスコープに分けて管理でき、リポジトリに含める共有設定と、個人のローカル環境限定の設定を分離することが推奨される。
- 破壊的な操作（`git push --force`、ファイル削除など）に対しては、デフォルトで確認を求める、あるいは明示的に許可リスト/拒否リストで制御するのが安全な運用（Security and Safetyドメインの最小権限原則と直結）。

## サブエージェント

- 特定の役割・コンテキストに特化した「サブエージェント」を定義し、メインのエージェントから委譲的に呼び出せる機能。
- 用途例：コードレビュー専用のサブエージェント、大規模な調査・検索専用のサブエージェントなど、役割を分離することでメインの会話コンテキストを圧迫せずに済む。
- Agents and Workflowsドメインで扱う「オーケストレーター/サブエージェント」パターンの実製品での実装例と位置づけられる。

## 押さえておくべきポイント

- Claude CodeがClaude Agent SDK上に構築された、実運用向けのコーディングエージェント製品であることを理解している。
- スラッシュコマンド（ビルトイン/カスタム）の役割と、定型タスクのテンプレート化に使える点を説明できる。
- フックが「決定論的に必ず実行させたい処理」をモデルの指示への依存なしに実現する仕組みであることを理解している。
- MCPサーバーとの連携により外部システムへのアクセスを拡張できることを理解している。
- パーミッション設定がプロジェクト/ユーザースコープで分離管理でき、破壊的操作への確認フローが安全設計の要であることを説明できる。
- サブエージェントが、コンテキスト分離とタスク専門化を実現する仕組みであることを理解している。
