# 02. Tool Design & MCP Integration(18%)

> **出典**: 公式の試験ガイド(Claude Certified Architect – Foundations、バージョン1.0)のタスク記述2.1〜2.5と、[MCP仕様](https://modelcontextprotocol.io/specification/latest)・[Claude CodeのMCPドキュメント](https://code.claude.com/docs/en/mcp)に基づく要約。

## この分野が扱うこと

エージェントがツールを選び、使い、失敗から回復できるように、ツールのインターフェースとMCP連携を設計する。ツールの説明文の書き方、構造化されたエラー、ツールの振り分け、MCPサーバーの設定、組み込みツールの使い分けが柱になる。

## 2.1 ツールインターフェースの設計:明確な説明と境界

- **説明文は、モデルがツールを選ぶ主な手がかり**。説明が最小限だと、似たツールの間で選択が不安定になる。
- 説明に含めるもの: 入力の形式、クエリの例、エッジケース、他のツールとの境界(いつこのツールを使い、いつ別のツールを使うか)。
- **説明が曖昧・重複すると誤ルーティングが起きる**。
  - 例: `analyze_content`と`analyze_document`の説明がほぼ同じだと、どちらが選ばれるか不安定になる。
- **対処**:
  - 機能の重複をなくすように、ツール名と説明を直す(例: `analyze_content`を、Web用と分かる`extract_web_results`に改名する)
  - 汎用ツールを、入出力の契約が明確な目的別ツールに分割する(例: `analyze_document`を、`extract_data_points`・`summarize_content`・`verify_claim_against_source`に分ける)
- **システムプロンプトの文言も影響する**。キーワードに反応する指示が、意図しないツールとの結びつきを生み、よく書かれたツール説明を上書きしてしまうことがある。システムプロンプトを見直す。

## 2.2 MCPツールの構造化されたエラー応答

- **`isError`フラグ**: MCPでツールの失敗をエージェントに伝える仕組み。
- **エラーの種類を区別する**: 一過性(タイムアウト、サービス停止)、検証(入力が不正)、ビジネス(ポリシー違反)、権限。
- **一律の「操作に失敗しました」ではだめ**。エージェントが適切な回復判断をできない。
- **返すべきメタデータ**:
  - `errorCategory`(transient / validation / permission など)
  - `isRetryable`(再試行してよいか)
  - 人が読める説明
  - ビジネスルール違反には、再試行不可(`retriable: false`)を示し、顧客向けに説明できる文面を付ける
- **サブエージェント内でのローカル回復**: 一過性の障害は、サブエージェント内で解決する。解決できなかったエラーだけを、部分的な結果と「何を試したか」を添えて、コーディネーターに伝える。
- **アクセス失敗と、有効な空の結果を区別する**: 前者は再試行の判断が必要。後者は「照会は成功したが該当なし」という正常な結果。

## 2.3 エージェント間のツール配分と`tool_choice`

- **ツールが多すぎると選択精度が落ちる**(例: 4〜5個で足りるのに18個渡す)。判断が複雑になるため。
- **専門外のツールは誤用されやすい**(例: 統合担当のエージェントがWeb検索を試みる)。
- **役割に応じたスコープ**: 各エージェントには、役割に必要なツールだけを渡す。頻度の高い横断的な必要には、限定した横断ツールを例外的に与える。
- **制約付きの代替ツール**: 汎用的な`fetch_url`の代わりに、URLを検証する`load_document`を渡す。
- **横断ツールの例**: 統合エージェントに`verify_fact`を持たせ、複雑なケースはコーディネーター経由にする。
- **`tool_choice`の設定**:
  - `"auto"`: モデルがツールを呼ばず、テキストを返すこともある
  - `"any"`: 必ずいずれかのツールを呼ぶ(どれかはモデルが選ぶ)
  - 指定ツール(`{"type": "tool", "name": "..."}`): 指定したツールを必ず呼ぶ
- **使いどころ**:
  - 指定ツールの強制は、特定の処理を最初に実行させたいとき(例: `extract_metadata`を先に走らせてから、他のツールに進む)。後続のステップは次のターンで処理する。
  - `"any"`は、会話的なテキストではなく、必ずツール呼び出しにしたいとき(文書の種類が不明で、複数の抽出スキーマがあるときなど)。

## 2.4 Claude CodeとエージェントのワークフローへのMCPサーバー統合

- **スコープ**:
  - プロジェクトレベルの`.mcp.json`は、チームで共有するツール用。Gitにコミットして共有する
  - ユーザーレベルの`~/.claude.json`は、個人用・試験的なサーバー用
- **環境変数の展開**: `.mcp.json`で`${GITHUB_TOKEN}`のように参照し、秘密情報をコミットせずに認証情報を渡す。`${VAR:-default}`で既定値も指定できる。
- **全サーバーのツールが同時に使える**: 設定済みのすべてのMCPサーバーのツールは、接続時に検出され、エージェントが同時に使える。
- **同名サーバーの優先順位**: `local` → `project` → `user`の順で、優先度の高い定義が丸ごと使われる(フィールドはマージされない)。
- **ツール名の形式**: `mcp__<サーバー名>__<ツール名>`。権限ルールやフックのマッチャーに使う(`mcp__memory__.*`など)。
- **MCPリソース**: 課題の要約、ドキュメント階層、DBスキーマなど、コンテンツのカタログを公開できる。エージェントが探索のためにツールを何度も呼ぶ必要が減る。
- **ツールの説明を充実させる**: 機能と出力を詳しく書かないと、エージェントがGrepなどの組み込みツールを選び、より高機能なMCPツールを使わなくなる。
- **既存のMCPサーバーを優先**: Jiraなどの標準的な連携は、コミュニティの既存サーバーを使う。自作は、チーム固有のワークフローに限る。
- **出力のサイズ制限**: ツール出力は10,000トークンで警告、既定25,000トークンが上限。巨大な結果は、サーバー側でページングや絞り込みを提供する。
- **仕様上の注意**: ツールの挙動を説明するannotationsは、信頼できるサーバーから得たものでない限り信頼しない。

## 2.5 組み込みツール(Read、Write、Edit、Bash、Grep、Glob)の使い分け

- **Grep**: ファイルの**内容**を検索する(関数名、エラーメッセージ、import文など)。
- **Glob**: ファイルの**パス**をパターンで探す(名前や拡張子。例: `**/*.test.tsx`)。
- **Read / Write**: ファイル全体の読み書き。**Edit**: 一意なテキストに一致させた部分的な変更。
- **Editが失敗するとき**: 一致するテキストが一意でない場合。その場合は、Readで全体を読み、Writeで書き込む方法に切り替える。
- **コードベースの理解は段階的に**:
  1. Grepで入り口を探す
  2. Readでimportを追い、流れをたどる
  3. 最初に全ファイルを読むことは避ける
- **ラッパーモジュール経由の使用をたどる**: まずエクスポートされている名前をすべて特定し、それぞれをコードベース全体で検索する。

## 補足:権限・設計上の観点

- ツールは最小権限にする。汎用的すぎるツール(任意のコマンド実行など)は誤用・悪用のリスクが大きい。
- ツールの名前とスキーマはAPIの契約。破壊的変更は、新しい名前やバージョンで提供する。説明文の変更も挙動に影響するため、契約の変更として扱う。
- 監査ログとして、誰がいつどのツールをどの引数で呼んだかを記録できるようにする。

## 押さえておくべきポイント

- ツール選択は説明文で決まる。入力形式・例・境界・他ツールとの違いを書く。曖昧な重複は、改名と説明の修正、または目的別への分割で解消する
- システムプロンプトの文言がツール選択に影響することがある
- ツールの失敗は`isError`で返し、`errorCategory`・`isRetryable`・説明を付ける。一律の失敗メッセージは回復判断を妨げる
- アクセス失敗(再試行を判断する)と、有効な空の結果(正常)を区別する
- ツールは役割ごとに絞る(4〜5個)。`tool_choice`は`auto`・`any`・指定ツールの3種類で、指定ツールは「最初にこの処理を」、`any`は「必ずツール呼び出しに」
- MCPのチーム共有は`.mcp.json`+環境変数展開、個人用は`~/.claude.json`。リソースでカタログを見せ、ツール説明を充実させる
- Grepは内容、Globはパス。Editが一意に一致しないときは、Read+Writeで代替する
